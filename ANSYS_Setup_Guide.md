# ANSYS 2-D/3-D AMR Regenerator-Bed Setup Guide

## Status

**This is a setup specification, not a validated result**, for exactly
the same reason as `COMSOL_SETUP_GUIDE.md`: no ANSYS license was
available in the environment this repo was developed in, so nothing
below has actually been built, meshed, or solved. This guide specifies
the same physical model as the COMSOL guide — same geometry, same
material properties, same MCE source term, same degeneracy-check target
— translated into ANSYS Fluent's porous-media + UDF workflow instead of
COMSOL's Brinkman-equations + interpolation-function workflow. If both
guides are ever built out, they should be checked against **the same
benchmark number** (§7-8) and against **each other**, not just against
the 0-D model independently — a genuine agreement between two
independently-implemented 2-D/3-D solvers would be much stronger
evidence than either one alone.

Read `COMSOL_SETUP_GUIDE.md` first if you haven't — this guide assumes
the same physics and mostly covers *where the ANSYS workflow differs*,
rather than re-deriving everything from scratch.

## 0. Why this exists / scope

Identical to `COMSOL_SETUP_GUIDE.md` §0-1: `core/amr_cycle.py` is a
lumped 0-D model; this guide specifies a spatially-resolved single-cell
regenerator model (packed-bed or parallel-plate, one AMR cycle) to check
whether that 0-D model's structural approximations — the linear
`span_fraction` cutoff, the fixed-mdot geometry sweeps in
`core/geometry_analysis.py`, the phenomenological `(1 - 0.3U)` utilization
correction in `core/thermal.py` — hold up once real gradients are
resolved. Same out-of-scope list applies: no Curie-graded multi-layer
bed, no solved magnet-circuit field, no structural/mechanical analysis.

## 1. Tool choice within ANSYS

- **ANSYS Fluent** — recommended primary tool. Its Porous Zone model
  (Cell Zone Conditions → Porous Zone) natively supports the
  viscous/inertial resistance coefficients this problem needs, and its
  UDF (User-Defined Function) framework is the natural place to
  implement the MCE volumetric source term, since it needs to switch on
  and off with cycle phase and depend on local cell temperature — not a
  static material property.
- **ANSYS Mechanical / Maxwell** — out of scope for this guide (no
  structural or magnetic-circuit analysis specified here), but would be
  the natural tool if a follow-on step ever solves the actual permanent-
  magnet field distribution instead of prescribing a uniform `H(t)`
  waveform, or checks regenerator-housing thermal stress from the cyclic
  temperature swing.
- **ANSYS CFX** is a viable alternative to Fluent for the porous-flow
  part but has a less flexible user-source-term mechanism (CEL
  expressions vs. Fluent's compiled/interpreted UDFs) for something as
  cycle-dependent as the MCE source term; Fluent is the more direct
  match to what §4 below needs.

The rest of this guide assumes **Fluent**.

## 2. Governing physics (same as COMSOL guide, different implementation surface)

### 2.1 Fluid domain — porous zone

Set the bed as a **Porous Zone** in Fluent's Cell Zone Conditions, with
viscous resistance (`1/α`) and inertial resistance (`C2`) coefficients
derived from the SAME friction-factor correlations
`core/thermal.py`/`COMSOL_SETUP_GUIDE.md` §2.1 use — do not accept
Fluent's own Ergun-equation porous-media defaults without checking they
match:

- **Packed bed**: `f = 23.462 · Re^-0.6716` (Tušek et al. 2013 Eq. 5,
  `10 < Re < 5e5`). Convert to Fluent's `ΔP = (μ/α)·v + C2·(1/2)ρ·v²`
  form by fitting `α` and `C2` against this `f(Re)` over the Reynolds
  range the operating point actually spans (see §7) — a single-point
  linear/quadratic fit is not adequate if Re varies significantly across
  the cycle (flow is zero during magnetize/demagnetize, so this mostly
  matters within the flow-on steps).
- **Parallel plate**: laminar `f = 24/Re` (Eq. 6, `Re < 2300`) — this
  is pure viscous drag, so `C2 ≈ 0` and `α` follows directly from
  Poiseuille flow between plates of spacing `2·d_h⁻¹`... (see COMSOL
  guide §2.1/§3.2 for the exact hydraulic-diameter definition, Eq. 7's
  slot limit).
- Hydraulic diameter, porosity, specific surface area: identical
  definitions to `COMSOL_SETUP_GUIDE.md` §2.1 and §3 — reuse those
  tables rather than re-deriving them.

### 2.2 Solid domain — MCE heat source via UDF

This is the part that differs most from COMSOL. Implement the MCE
volumetric source term as a **`DEFINE_SOURCE` UDF**, hooked to the
Energy equation in the solid (or porous-solid) zone, e.g.:

```c
#include "udf.h"

/* Lookup table generated by core/mce_material.py -- see §2.3 below.
   Loaded at UDF init from the same CSV the COMSOL guide's §2.3 script
   produces (gd_dTad_vs_T_1p13T.csv), NOT re-derived inside the UDF. */
extern real dTad_lookup(real T);
extern real Ctotal_lookup(real T);

DEFINE_SOURCE(mce_source, cell, thread, dS, eqn)
{
    real T = C_T(cell, thread);
    real rho_solid = 7900.0;          /* core/thermal.py::RHO_GD */
    real q = 0.0;

    /* cycle_phase and t_mag are set by DEFINE_EXECUTE_AT_END or a
       global UDM (User-Defined Memory) driven by a separate cycle-
       timing UDF -- see §5. Sign flips between magnetize (+1) and
       demagnetize (-1); zero during the two flow phases. */
    if (cycle_phase == MAGNETIZE)
        q = rho_solid * Ctotal_lookup(T) * dTad_lookup(T) / t_mag;
    else if (cycle_phase == DEMAGNETIZE)
        q = -rho_solid * Ctotal_lookup(T) * dTad_lookup(T) / t_mag;

    dS[eqn] = 0.0;   /* source term has no explicit T-dependence needed
                         for a converged linearization here; revisit if
                         convergence is poor near Tc where dTad_lookup
                         has its sharpest curvature */
    return q;
}
```

`dTad_lookup`/`Ctotal_lookup` should read the same CSV table
`COMSOL_SETUP_GUIDE.md` §2.3 specifies (generated directly from
`core/mce_material.py::MagnetocaloricMaterial.delta_T_adiabatic()` /
`.total_heat_capacity()`), via a simple piecewise-linear interpolation
over the tabulated `(T, ΔT_ad, C_total)` triples — loaded once at
`DEFINE_INIT` via Fluent's UDF file I/O, not hardcoded as a polynomial
fit. **This is the same requirement as the COMSOL guide's §2.2-2.3**:
the point is that both FEA tools' source term is provably tied to this
repo's own validated material model, not a re-derivation that could
silently diverge from it.

### 2.3 Generating the lookup table

Identical Python snippet to `COMSOL_SETUP_GUIDE.md` §2.3 — reuse the
same CSV, don't regenerate it with different field/temperature bounds
for the two guides, or the COMSOL and Fluent results stop being
comparable to each other.

## 3. Geometry and mesh

Same unit-cell geometry as `COMSOL_SETUP_GUIDE.md` §3 (packed bed:
d_p=0.5mm default, ε=0.365, 0.002 m² cross-section; parallel plate:
0.1-0.2mm spacing, 0.5mm plate thickness) — build the same CAD geometry
in Fluent's meshing tool (Fluent Meshing / Watertight Geometry workflow,
or SpaceClaim if extruding a swept 3-D unit cell). Recommended mesh
guidance for Fluent specifically:

- Use a **structured/swept mesh** along the flow direction where
  possible (porous-zone flows don't need boundary-layer-resolved cells
  the way a fully-resolved packed-bed CFD would, since the porous model
  is already a volume-averaged approximation) — this keeps element count
  and solve time down for what's meant to be a unit-cell check, not a
  full-device CFD study.
- Mesh independence check: halve the axial cell count and confirm Qc at
  the periodic-steady operating point (§7) changes by less than ~2%
  before trusting any geometry-sensitivity conclusion — the same
  discipline `core/geometry_analysis.py`'s own sweeps apply at the 0-D
  level (multiple resolution points per sweep, not a single value).

## 4. Material properties

Identical table to `COMSOL_SETUP_GUIDE.md` §4 — same Gd density (7900
kg/m³), lattice `Cp` (236 J/(kg·K), with the same caveat about using the
full `total_heat_capacity(T)` table near Tc instead of this flat
constant), Tc (294.0 K), Debye temperature (169.0 K), molar mass (157.25
g/mol), and water properties (997 kg/m³, 4186 J/(kg·K), 8.9e-4 Pa·s,
0.606 W/(m·K)). In Fluent, set these via the Materials panel; for water,
prefer Fluent's built-in temperature-dependent property database over
the constant values above if the model spans a temperature range wide
enough for it to matter (same note as the COMSOL guide's §4).

## 5. AMR cycle timing (Fluent Named Expressions / UDF-driven state machine)

Same four-step cycle as `COMSOL_SETUP_GUIDE.md` §5. Fluent has no direct
equivalent to COMSOL's Events interface, so implement the cycle as an
explicit state machine:

1. A `DEFINE_EXECUTE_AT_END` UDF that tracks elapsed time (via Fluent's
   `CURRENT_TIME` macro) against the cycle period `1/frequency` and blow
   fraction (`core/amr_cycle.py::BLOW_FRACTION_MASCHE`, default 0.5),
   updating a global/UDM flag for which of the four phases the solver is
   currently in.
2. That flag gates: (a) the `DEFINE_SOURCE` UDF in §2.2 (source active
   only during magnetize/demagnetize), and (b) the inlet boundary
   condition's mass-flow-rate profile (flow only during the two flow
   phases, direction reversing between cold→hot and hot→cold).
3. Run enough full periods for the bed's periodic-steady-state
   temperature profile to converge (same convergence criterion as the
   COMSOL guide §5 — cycle-to-cycle ΔT below a small tolerance at every
   monitored point) before reading off Qc.

## 6. Boundary conditions

Identical to `COMSOL_SETUP_GUIDE.md` §6: fixed-temperature cold/hot
reservoirs (Fluent: `pressure-outlet`/`velocity-inlet` boundary pairs
gated by the same phase flag as §5, with `Temperature` BC set to
`T_cold`/`T_hot` respectively only when that boundary is the active
inflow), adiabatic bed walls as the first-pass assumption (matching the
0-D model's lack of any wall-loss term — flag explicitly if this is
later relaxed), mass flow rate from §7's calibrated `mdot`.

## 7. Operating point for the degeneracy check

**Use the exact same benchmark as `COMSOL_SETUP_GUIDE.md` §7** —
DTU_Eriksen_rotary_Gd_2015, the one device in
`data/amr_experimental_benchmarks.csv` that calibrates cleanly under
this repo's 0-D model:

| Parameter | Value |
|---|---|
| Material | Gd (single-Tc approximation) |
| μ0H_max | 1.13 T |
| Regenerator mass | 1.7 kg |
| Frequency | 0.75 Hz |
| T_cold | 289 K |
| Span | 10.2 K |
| Calibrated mdot | 0.084666 kg/s |
| Target Qc | 102.8 W |
| Target COP | 3.1 (this repo's 0-D model: -2.1% error, `implied_parasitic=0.255`) |

doi:10.1016/j.ijrefrig.2015.05.004.

## 8. Degeneracy check (do this before trusting anything else)

Same standard as `COMSOL_SETUP_GUIDE.md` §8: reproduce Qc≈102.8W at
span=10.2K before trusting any new geometry or gradient conclusion from
the Fluent model. If it doesn't land within roughly the 0-D model's own
-2.1% error band (generously ±10-15% to allow for genuine spatial
effects), the most likely explanations are a UDF unit error, a wrong
blow-fraction assumption, or an unconverged periodic-steady state — check
those before treating a mismatch as a physical finding. **If both the
COMSOL and Fluent models are eventually built, cross-checking them
against each other, in addition to this benchmark, is the strongest
validation step available** — two independently-coded solvers agreeing
with each other and with the literature number is meaningfully stronger
evidence than either one alone.

## 9. What a working Fluent model would add beyond the 0-D model

Same list as `COMSOL_SETUP_GUIDE.md` §9: real axial gradients within the
bed; a direct check on whether the `amr_cycle.py`'s linear
`span_fraction` cutoff near the no-load span limit is a reasonable
approximation (that function's own docstring already flags it as
producing an artificially sharp corner vs. the gradual rolloff published
Qc(span) curves show); whether the fixed-mdot geometry optimum
`core/geometry_analysis.py` finds survives joint mdot+geometry
optimization once gradients are resolved; and, if extended to a graded
bed, whether inter-layer axial conduction (currently ignored by
`cascade.py`'s independently-peak-tuned-layer treatment) matters.

## 10. Known limitations of this guide itself

- Never built or solved (§0).
- MCE source term inherits the mean-field model's documented
  overprediction of ΔT_ad near Tc at low field (`core/validation.py`).
- Water properties as constants unless explicitly upgraded (§4).
- No wall-conduction/radiative loss term specified (§6).
- Uniform, prescribed magnetic field — no solved magnet-circuit model.
- The UDF-based cycle state machine in §5 is a genuine additional
  implementation surface (compiled C code, not a built-in solver
  feature) compared to COMSOL's Events interface — more room for a
  units/logic bug to hide, which is exactly why §8's degeneracy check
  matters more here, not less.
